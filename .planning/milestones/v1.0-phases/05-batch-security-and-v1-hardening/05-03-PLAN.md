<threat_model>

## Trust Boundaries

| Boundary              | Description                                         |
| --------------------- | --------------------------------------------------- |
| GitHub Actions -> npm | OIDC token exchange crosses from CI to npm registry |
| PR -> CI              | Untrusted PR code triggers CI pipeline              |

## STRIDE Threat Register

| Threat ID | Category               | Component   | Disposition | Mitigation Plan                                                                                                                                                            |
| --------- | ---------------------- | ----------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-05-11   | Spoofing               | release.yml | mitigate    | npm OIDC trusted publishing eliminates long-lived npm tokens. Only workflows from the configured GitHub repo/environment can publish. No secrets to leak                   |
| T-05-12   | Tampering              | release.yml | mitigate    | npm provenance attestation (NPM_CONFIG_PROVENANCE=true) creates a verifiable link between the published package and its source commit. Consumers can verify package origin |
| T-05-13   | Elevation of Privilege | ci.yml      | accept      | PR CI runs with read-only permissions (no write access to npm or GitHub). publish dry-run uses --dry-run flag — no actual publish occurs                                   |

</threat_model>
