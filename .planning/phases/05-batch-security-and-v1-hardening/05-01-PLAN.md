<threat_model>

## Trust Boundaries

| Boundary               | Description                                                           |
| ---------------------- | --------------------------------------------------------------------- |
| client -> POST /$batch | Untrusted multipart/mixed body crosses into server parsing            |
| batch sub-request URL  | Untrusted URL path from batch body used to route to handlers          |
| batch sub-request body | Untrusted JSON body from batch parts used for entity creation/updates |

## STRIDE Threat Register

| Threat ID | Category               | Component                 | Disposition | Mitigation Plan                                                                                                                                                                               |
| --------- | ---------------------- | ------------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-05-01   | Tampering              | batch-parser.ts           | mitigate    | Validate boundary format, reject bodies exceeding max batch size (configurable, default 100 operations). Malformed parts throw ODataValidationError (400), never pass through                 |
| T-05-02   | DoS                    | batch-controller.ts       | mitigate    | Limit max operations per batch request (default 100). Reject with 400 if exceeded. Prevents unbounded transaction size                                                                        |
| T-05-03   | Injection              | batch-controller.ts       | mitigate    | Sub-request URLs are parsed via regex to extract entitySetName and key only — never passed to shell or eval. Entity operations go through TypeORM parameterized queries (same as direct CRUD) |
| T-05-04   | Spoofing               | batch-controller.ts       | accept      | Batch endpoint inherits the same NestJS guards as direct endpoints. No additional auth needed at $batch level — sub-requests run with the same principal                                      |
| T-05-05   | Information Disclosure | batch-response-builder.ts | mitigate    | Failed changeset responses use ODataExceptionFilter-style error formatting — no stack traces, no internal details. Only error.code and error.message exposed                                  |

</threat_model>
