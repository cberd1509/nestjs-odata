    import { ODATA_ETAG_KEY } from './metadata-keys.js'

    /**
     * Marks a property as the ETag source for concurrency control.
     * Per D-03: opt-in per entity. Only entities with @ODataETag or @UpdateDateColumn get ETags.

<threat_model>

## Trust Boundaries

| Boundary                              | Description                                                        |
| ------------------------------------- | ------------------------------------------------------------------ |
| Client If-Match header -> server      | Untrusted input: client sends ETag value that server must validate |
| Client If-None-Match header -> server | Untrusted input: cache validation header                           |
| Entity data -> ETag computation       | Internal: server reads entity column to compute ETag               |

## STRIDE Threat Register

| Threat ID | Category               | Component           | Disposition | Mitigation Plan                                                                                                                                                                           |
| --------- | ---------------------- | ------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-09-04   | Tampering              | If-Match validation | mitigate    | Server always recomputes ETag from current DB state before comparing — client cannot influence the server-side ETag computation. Stale or forged If-Match values are rejected with 412.   |
| T-09-05   | Spoofing               | ETag value          | accept      | ETag values are derived from @UpdateDateColumn timestamps. They are not secrets — they indicate entity version. Knowing an ETag does not grant access.                                    |
| T-09-06   | Denial of Service      | ETag computation    | mitigate    | ETag computation uses simple base64 encoding (no expensive crypto). Per-entity caching of ETag column name prevents repeated metadata reflection.                                         |
| T-09-07   | Information Disclosure | ETag header         | accept      | Weak ETags (W/"...") expose a hash of the updatedAt timestamp. This reveals approximate last-modification time, which is acceptable for non-sensitive entity metadata.                    |
| T-09-08   | Repudiation            | If-Match bypass     | mitigate    | If-Match is optional per OData spec — if omitted, update proceeds (last-write-wins). This is spec-compliant. Applications requiring mandatory concurrency control can add a NestJS guard. |

</threat_model>
