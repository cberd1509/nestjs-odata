<objective>
Add OData v4 metadata annotations (@odata.id, @odata.type, @odata.navigationLink) to every entity response.

Purpose: OData v4 spec requires entity responses to carry metadata annotations so clients can construct canonical URLs, identify entity types, and discover navigation links. This is foundational for ETag support (Plan 02) which adds @odata.etag alongside these annotations.

Output: `annotateEntity()` pure function in core, integrated into the existing `ODataResponseInterceptor`, with full unit test coverage.
</objective>

## STRIDE Threat Register

| Threat ID | Category               | Component      | Disposition | Mitigation Plan                                                                                                                                                                                                       |
| --------- | ---------------------- | -------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-09-01   | Information Disclosure | annotateEntity | mitigate    | Key values in @odata.id URLs are already public (they come from the entity's primary key which is in the response). Navigation link URLs only reveal property names already in $metadata. No new information exposed. |
| T-09-02   | Tampering              | annotateEntity | accept      | Annotations are read-only server-generated metadata. Client cannot tamper with them.                                                                                                                                  |
| T-09-03   | Spoofing               | @odata.id URL  | mitigate    | URLs are constructed from serviceRoot (server config) + entitySetName (server metadata) + key (entity data). No user input in URL construction.                                                                       |

</threat_model>
