    However, PATH_METADATA is read at module compile time (before onModuleInit). The MetadataController pattern works because `createMetadataControllerWithPath()` runs synchronously inside `forRoot()`.

    For @ODataController, the correct approach is to patch paths in `ODataTypeOrmModule.forFeature()` synchronously:

    ```typescript
    static forFeature(
      entities: EntityClassOrSchema[],
      controllers?: (new (...args: unknown[]) => unknown)[],
    ): DynamicModule {
      // Patch @ODataController paths with serviceRoot
      // Since serviceRoot is not available here (it's in forRoot), controllers
      // must specify their path via @ODataController(entitySetName) which sets
      // Controller(entitySetName). The serviceRoot prefixing must happen in forRoot.
      // ...
    ```

    Since `forFeature()` does not have access to serviceRoot (it comes from forRoot()), the path patching cannot happen in forFeature. There are two options:

    **Option A (selected):** `@ODataController(entitySetName)` sets `Controller(entitySetName)` directly. The user provides the full desired path OR the module uses a post-init path resolution. Since NestJS reads PATH_METADATA before onModuleInit, the only reliable approach is that @ODataController sets the entity set name as the path, and users configure their NestJS global prefix to act as the service root: `app.setGlobalPrefix('odata')`. This is simpler and more NestJS-idiomatic.

    However, D-17 says "service root is applied by the @ODataController decorator, not as a NestJS global prefix." To honor D-17 strictly:

    **Option B (honoring D-17):** Add a `patchODataControllerPaths(controllers, serviceRoot)` function that is called synchronously in `ODataModule.forRoot()`. The forRoot method accepts an optional `controllers` parameter. This ensures PATH_METADATA is set before module compilation.

    Update `packages/core/src/odata.module.ts` to add a static helper:

    ```typescript
    /**
     * Patch @ODataController paths to prepend the serviceRoot.
     * Must be called synchronously in forRoot() before module compilation.
     * Per D-17: service root is applied by the module system.
     */
    static patchControllerPaths(
      controllers: (new (...args: unknown[]) => unknown)[],
      serviceRoot: string,
    ): void {
      const root = serviceRoot.startsWith('/') ? serviceRoot.slice(1) : serviceRoot
      for (const ctrl of controllers) {
        const entitySetName = Reflect.getMetadata(ODATA_CONTROLLER_KEY, ctrl)
        if (entitySetName) {
          const fullPath = root ? `${root}/${entitySetName}` : entitySetName
          Reflect.defineMetadata(PATH_METADATA, fullPath, ctrl)
        }
      }
    }
    ```

    And consumers call `ODataModule.patchControllerPaths(controllers, serviceRoot)` in their AppModule, or the ODataModule.forRoot accepts controllers:

    Actually the simplest approach that honors D-17: add `controllers` to `ODataModuleOptions` and patch in `forRoot()`:

    ```typescript
    export interface ODataModuleOptions {
      serviceRoot: string
      namespace?: string
      maxTop?: number
      maxExpandDepth?: number
      unmappedTypeStrategy?: UnmappedTypeStrategy
      /** OData controllers to register. Paths are prefixed with serviceRoot. */
      controllers?: (new (...args: unknown[]) => unknown)[]
    }
    ```

    In `ODataModule.forRoot()`:
    ```typescript
    static override forRoot(options: ODataModuleOptions): DynamicModule {
      const parent = super.forRoot(options)
      const metadataController = createMetadataControllerWithPath(options.serviceRoot)

      // Patch @ODataController paths per D-17
      if (options.controllers) {
        const root = options.serviceRoot.startsWith('/')
          ? options.serviceRoot.slice(1)
          : options.serviceRoot
        for (const ctrl of options.controllers) {
          const entitySetName = Reflect.getMetadata(ODATA_CONTROLLER_KEY, ctrl)
          if (entitySetName) {
            Reflect.defineMetadata(PATH_METADATA, `${root}/${entitySetName}`, ctrl)
          }
        }
      }

      return {
        ...parent,
        providers: [...(parent.providers ?? []), resolvedOptionsProvider, CsdlBuilder, ServiceDocumentBuilder],
        controllers: [...(parent.controllers ?? []), metadataController, ...(options.controllers ?? [])],
        exports: [...(parent.exports ?? []), ODATA_MODULE_OPTIONS, CsdlBuilder],
      }
    }
    ```

    - Routes register at `/odata/Products`, `/odata/Products/:key`, etc.
