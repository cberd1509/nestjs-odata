## STRIDE Threat Register

| Threat ID | Category          | Component                 | Disposition | Mitigation Plan                                                                                                                                                                                                                                   |
| --------- | ----------------- | ------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-04-01   | Denial of Service | parseExpand               | mitigate    | Recursive $expand parsing inherits the max nesting depth (50) from the parser. Nested expand uses recursive parseQuery which re-enters the parser with the same depth protection.                                                                 |
| T-04-02   | Tampering         | parseODataKey             | mitigate    | Key values are returned as typed JS values (number, string, boolean) — never interpolated into SQL. TypeORM receives them as parameterized where clause values via repo.findOne({ where }).                                                       |
| T-04-03   | Denial of Service | parseExpand nested parens | mitigate    | The top-level comma splitter tracks parenthesis depth to avoid incorrect splitting. Malformed nested parens (unclosed) will result in the entire remainder being treated as a single segment, which parseQuery will reject or produce no results. |
