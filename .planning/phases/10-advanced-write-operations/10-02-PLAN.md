    1. **Add resolveContentIdReferences() private method** to `BatchController` in `packages/typeorm/src/batch/batch-controller.ts`:

       ```typescript
       private resolveContentIdReferences(
         part: BatchRequestPart,
         contentIdMap: ReadonlyMap<string, string>,
       ): BatchRequestPart {
         if (contentIdMap.size === 0) return part  // fast path

         let url = part.url
         let body = part.body

         for (const [id, resolvedUrl] of contentIdMap) {
           // Match $<id> at word boundary or before /
           const pattern = new RegExp(`\\$${id}(?=[/?#]|$)`, 'g')
           url = url.replace(pattern, resolvedUrl)
           if (body) {
             body = body.replace(pattern, resolvedUrl)
           }
         }

         return url === part.url && body === part.body
           ? part
           : { ...part, url, ...(body !== part.body ? { body } : {}) }
       }
       ```

## Trust Boundaries

| Boundary                    | Description                                                                               |
| --------------------------- | ----------------------------------------------------------------------------------------- |
| client -> POST deep insert  | Untrusted nested body may contain arbitrary depth, invalid FKs, or extra navigation paths |
| client -> $batch Content-ID | Crafted $N patterns in URL or body could reference unintended resources                   |

## STRIDE Threat Register

| Threat ID | Category               | Component                                            | Disposition | Mitigation Plan                                                                                                                                                                                                        |
| --------- | ---------------------- | ---------------------------------------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-10-05   | Denial of Service      | handleDeepCreate unbounded recursion                 | mitigate    | maxDeepInsertDepth config (default 5) checked before each recursive call. Depth counter incremented at each level.                                                                                                     |
| T-10-06   | Tampering              | Deep insert mass assignment via nested body          | mitigate    | TypeORM repo.create() only maps declared columns on each entity class -- unknown fields in nested objects silently ignored. Same pattern as existing handleCreate.                                                     |
| T-10-07   | Tampering              | Content-ID injection via crafted $N in body          | accept      | $N resolves only from contentIdMap populated by prior 201 responses within the same changeset. String replacement only -- no code evaluation. Risk is low: worst case substitutes a valid URL from the same changeset. |
| T-10-08   | Information Disclosure | Content-ID map leaking across changesets             | mitigate    | contentIdMap declared as local variable inside executeChangeset() -- fresh Map for every changeset invocation.                                                                                                         |
| T-10-09   | Tampering              | Deep insert FK injection overriding user-supplied FK | accept      | The implementation injects the parent's generated PK as the child's FK, overwriting any user-supplied value. This is correct behavior -- the FK must match the parent, not the client's arbitrary value.               |
