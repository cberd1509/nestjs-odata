    - `Price gt 5 and Active eq true` -> BinaryExpr(BinaryExpr(Price gt 5), 'and', BinaryExpr(Active eq true))

    - `contains(Name,'widget')` -> FunctionCall('contains', [PropertyAccess(['Name']), Literal('widget')])
    - `startswith(Name,'A')` -> FunctionCall('startswith', ...)
    - `endswith(Name,'z')` -> FunctionCall('endswith', ...)
    - `tolower(Name) eq 'alice'` -> BinaryExpr(FunctionCall('tolower', ...), 'eq', Literal('alice'))
    - `Tags/any(t:t/Name eq 'electronics')` -> LambdaExpr('any', 'Tags', 't', BinaryExpr(...))
    - `Tags/all(t:t/Active eq true)` -> LambdaExpr('all', 'Tags', 't', BinaryExpr(...))
    - `Tags/any()` -> LambdaExpr('any', 'Tags', null, null) (no predicate)
    - `Category/Name eq 'Electronics'` -> BinaryExpr(PropertyAccess(['Category','Name']), 'eq', Literal('Electronics'))
    - `LastName eq 'O''Brien'` -> BinaryExpr(PropertyAccess(['LastName']), 'eq', Literal("O'Brien"))
    - String literal: `'hello'` -> Literal(literalKind='string', value='hello')
    - Integer: `42` -> Literal(literalKind='number', value=42)
    - Decimal: `3.14` -> Literal(literalKind='number', value=3.14)
    - Boolean: `true` -> Literal(literalKind='boolean', value=true)
    - Null: `null` -> Literal(literalKind='null', value=null)
    - GUID: `12345678-1234-1234-1234-123456789abc` -> Literal(literalKind='guid')
    - Parenthesized: `(Price gt 5)` -> same as `Price gt 5` (parens stripped)

    **Precedence (critical):**
    - `a or b and c` -> or(a, and(b, c)) — `and` binds tighter than `or`
    - `a and b eq c` -> and(a, eq(b, c)) — comparison binds tighter than logical
    - `a add b gt c` -> gt(add(a, b), c) — arithmetic binds tighter than comparison
    - `a mul b add c` -> add(mul(a, b), c) — multiplicative binds tighter than additive

    **$orderby parsing:**
    - `Name asc` -> OrderByItem(PropertyAccess(['Name']), 'asc')
    - `Name asc,Price desc` -> [OrderByItem(Name, asc), OrderByItem(Price, desc)]
    - `Name` -> OrderByItem(PropertyAccess(['Name']), 'asc') (default direction is asc)

    **$select parsing:**
    - `Name,Price` -> SelectItem(['Name']), SelectItem(['Price'])
    - `*` -> SelectAll

    **$top/$skip:**
    - `$top=10` -> top: 10
    - `$skip=20` -> skip: 20

    **Error cases:**
    - `Price gt` (missing right operand) -> ODataParseError with position info
    - `eq 5` (missing left operand) -> ODataParseError
    - `$top=-1` -> ODataParseError (negative not allowed)
    - Unknown function `foobar(x)` -> ODataParseError

  <implementation>
    **Architecture:** Lexer-first (tokenizer -> token stream -> parser).

    **Step 1: AST types (packages/core/src/parser/ast.ts)**
    Define discriminated unions per the research Pattern 5. Use `kind` as the discriminant field. Types:
    - FilterNode = BinaryExprNode | UnaryExprNode | FunctionCallNode | PropertyAccessNode | LiteralNode | LambdaExprNode
    - OrderByNode with items array (each item has expression + direction)
    - SelectNode with items array
    - QueryOptions aggregate type with optional filter, orderby, select, top, skip fields

    **Step 2: Visitor interface (packages/core/src/parser/visitor.ts)**
    Generic FilterVisitor<T> with one visit method per FilterNode variant.

    **Step 3: Lexer (packages/core/src/parser/lexer.ts)**
    Token types from research:
    STRING_LITERAL, INT_LITERAL, DECIMAL_LITERAL, BOOL_LITERAL, NULL_LITERAL, GUID_LITERAL, DATETIME_LITERAL,
    IDENTIFIER, OPEN_PAREN, CLOSE_PAREN, COMMA, SLASH, COLON,
    AND, OR, NOT, EQ, NE, LT, LE, GT, GE, HAS, IN,
    ADD, SUB, MUL, DIV, DIVBY, MOD, STAR, EOF

    The lexer must:
    - Handle OData string escaping ('' for single quote)
    - Distinguish keywords (and, or, not, eq, etc.) from identifiers by lookahead: keywords are followed by space/paren/EOF, identifiers are followed by slash/paren/space
    - Handle GUID pattern (8-4-4-4-12 hex chars)
    - Handle DateTimeOffset pattern
    - Skip whitespace between tokens

    **Step 4: Parser (packages/core/src/parser/parser.ts)**
    Recursive descent with Pratt/precedence climbing for binary operators.

    Precedence table (lowest to highest binding power):
    | Level | Operators | Binding |
    |-------|-----------|---------|
    | 1 | or | Left |
    | 2 | and | Left |
    | 3 | not | Prefix |
    | 4 | eq, ne, lt, le, gt, ge, has, in | Non-associative |
    | 5 | add, sub | Left |
    | 6 | mul, div, divby, mod | Left |
    | 7 | neg (unary minus) | Prefix |

    The `parseExpression(minPrecedence)` function:
    1. Parse left operand via `parsePrimary()`
    2. While the current token is a binary operator with precedence >= minPrecedence:
       a. Get operator precedence and associativity
       b. Advance past operator token
       c. Parse right operand via `parseExpression(nextMinPrecedence)` where nextMinPrecedence is precedence+1 for left-assoc, precedence for right-assoc
       d. Create BinaryExprNode with left, operator, right
       e. Set left = new BinaryExprNode
    3. Return left

    The `parsePrimary()` function handles:
    - Parenthesized expressions: `(` -> parseExpression(0) -> expect `)`
    - `not` prefix: parse operand at precedence 3
    - `-` (neg) prefix: parse operand at precedence 7
    - Function calls: identifier `(` -> parse comma-separated args -> `)`
    - Lambda expressions: identifier `/` identifier `(` [variable `:` expression] `)`
    - Property access: identifier (`/` identifier)*
    - Literals: string, number, boolean, null, GUID, DateTimeOffset

    Known built-in functions for validation: startswith, endswith, contains, indexof, substring, length, tolower, toupper, concat, year, month, day, hour, minute, second, round, floor, ceiling.

    **Step 5: Error handling (packages/core/src/parser/errors.ts)**
    ODataParseError extends Error with `position: number` and `token: Token | null` fields for diagnostic messages.

    **Step 6: Public API (packages/core/src/parser/index.ts + packages/core/src/index.ts)**
    Export `parseQuery(queryString: string): QueryOptions` as the main entry point. It parses `$filter=...&$orderby=...&$select=...&$top=...&$skip=...` into a QueryOptions object.
    Also export `parseFilter(filterString: string): FilterNode` for standalone filter parsing.
    Re-export all AST types and visitor interface from packages/core/src/index.ts.

     ```typescript
     class Parser {
       private tokens: Token[]
       private pos: number = 0

       constructor(tokens: Token[]) { this.tokens = tokens }

       private peek(): Token { return this.tokens[this.pos] }
       private advance(): Token { return this.tokens[this.pos++] }
       private expect(kind: TokenKind): Token { ... throw ODataParseError if mismatch }

       parseExpression(minPrecedence: number = 0): FilterNode {
         let left = this.parsePrimary()
         while (this.isBinaryOperator(this.peek()) && this.getPrecedence(this.peek()) >= minPrecedence) {
           const op = this.advance()
           const prec = this.getPrecedence(op)
           const assoc = this.getAssociativity(op)
           const nextMinPrec = assoc === 'left' ? prec + 1 : prec
           const right = this.parseExpression(nextMinPrec)
           left = { kind: 'BinaryExpr', operator: op.value as string, left, right }
         }
         return left
       }

       parsePrimary(): FilterNode {
         const token = this.peek()
         // Handle 'not' prefix
         if (token.kind === TokenKind.NOT) {
           this.advance()
           const operand = this.parseExpression(/* not precedence = 3 */)
           return { kind: 'UnaryExpr', operator: 'not', operand }
         }
         // Handle parenthesized
         if (token.kind === TokenKind.OPEN_PAREN) {
           this.advance()
           const expr = this.parseExpression(0)
           this.expect(TokenKind.CLOSE_PAREN)
           return expr
         }
         // Handle neg (unary minus via SUB token)
         if (token.kind === TokenKind.SUB) { ... }
         // Handle literals
         if (isLiteral(token)) { return this.parseLiteral() }
         // Handle identifier -> could be property, function call, or lambda
         if (token.kind === TokenKind.IDENTIFIER) {
           return this.parseIdentifierExpression()
         }
         throw new ODataParseError(`Unexpected token: ${token.kind}`, token.position, token)
       }

       // parseIdentifierExpression handles:
       // 1. identifier( -> function call
       // 2. identifier/identifier( -> lambda (any/all)
       // 3. identifier/identifier/... -> property access
       // 4. plain identifier -> property access with single segment
     }
     ```

   Associativity: OR, AND, ADD, SUB, MUL, DIV, DIVBY, MOD are left-associative. EQ/NE/LT/LE/GT/GE are non-associative (treat as left for simplicity — the spec says they don't chain).
